一、为什么需要 CSS 工具？

1.1 原生 CSS 的痛点

当你写过几百行 CSS 后，一定会遇到这些问题：

1.2 两类解决方案

类型 代表 思路
CSS 预处理器 Sass、Less 在 CSS 基础上增加编程特性（变量、嵌套、函数），编译后输出标准 CSS
CSS 框架 Tailwind CSS 提供一套预定义的工具类，直接在 HTML 中组合使用

简单理解：

  • 预处理器：让 CSS “能编程”
  • 框架：让 CSS “不用写”

二、Sass：最流行的 CSS 预处理器

2.1 Sass 是什么？

Sass（Syntactically Awesome Style Sheets）是 CSS 的超集，增加了变量、嵌套、混入、函数等编程特性。它有两种语法格式：

  • SCSS（推荐）：语法和 CSS 几乎一致，文件扩展名 .scss
  • Sass（缩进语法）：省略花括号和分号，文件扩展名 .sass

本文全部使用 SCSS 格式。

2.8 模块化：@use 与 @forward

Sass 官方已弃用 @import，推荐使用 @use 和 @forward。
@import 的问题是所有变量都变成全局的，容易导致命名冲突。
@use 通过命名空间隔离，更安全。

Less（Leaner Style Sheets）是另一个流行的 CSS 预处理器，语法和 Sass 类似但更轻量。它的核心理念是”尽可能像 CSS”。

3.8 Sass vs Less 对比

特性 Sass (SCSS) Less
变量符号 $variable @variable
嵌套 ✅ ✅
混入 @mixin / @include 直接引用类名或 .name()
继承 @extend :extend()
函数 丰富（自定义 + 内置） 较少（主要是内置）

模块系统 @use / @forward @import
社区活跃度 更高 逐渐减少
学习曲线 稍陡 更平缓

选择建议：

  • 新项目推荐 Sass——功能更强大，社区更活跃，Vue/React 生态默认支持更好。
  • 如果团队已有 Less 代码库，继续用 Less 也完全没问题。
  • 两者的核心思想是一样的，会一个再学另一个几乎零成本。

四、Tailwind CSS：实用优先的 CSS 框架

4.1 Tailwind 是什么？

Tailwind CSS 是一个实用优先（Utility-First）的 CSS 框架。它的核心理念和预处理器完全不同：

  • 预处理器：你自己写样式，工具帮你组织代码
  • Tailwind：框架提供大量预定义的工具类，你通过组合类名来构建界面

第一次看到 Tailwind 的 HTML 可能会觉得”这不就是行内样式吗？”
其实不是——Tailwind 的类是经过设计的约束系统（有固定的颜色、间距、字号规范），而行内样式是完全自由的（可以写任意值）。

5.2 核心对比

维度 Sass/Less Tailwind CSS
类型 预处理器 CSS 框架
思路 在 CSS 上加编程能力 提供预定义工具类

下一步…

  1. Sass 进阶：学习 @for 循环、@each 遍历、@function 自定义函数，构建实用的工具库
  2. Tailwind 进阶：学习 @tailwindcss/typography（排版插件）、@tailwindcss/forms（表单插件）
  3. CSS 架构：了解 BEM、OOCSS、ITCSS 等 CSS 架构方法论
  4. CSS-in-JS：了解 styled-components、emotion 等”在 JS 中写 CSS”的方案
  5. CSS 原生新特性：CSS Nesting（原生嵌套）、@layer、@container 等正在逐步取代预处理器的部分功能

CSS 工具的选择没有绝对的对错，关键是理解每个工具解决的是什么问题。
预处理器让 CSS “能编程”，Tailwind 让 CSS “不用写”。
掌握了这两种思路，面对任何项目都能找到合适的方案。

关于AI的使用：

你可以用 AI 来辅助理解和查找资料，但不要直接复制 AI 生成的代码，要自己动手写一遍。

Tailwind 的类名需要靠多写来记忆，Sass 的语法需要靠多用来熟练。看十遍不如自己写一遍。
