欢迎来到 React 的世界。

这篇文章写给已经掌握 HTML/CSS/JS 基础，想要学习 React 这个前端框架的读者：

  • 你知道 HTML 是结构、CSS 是样式、JS 是行为；
  • 你可能听说过 React、Vue、Angular 这些框架的名字；
  • 你好奇 React 到底是什么，和原生 JS 写页面有什么区别。

所以本文会按这个顺序来：

  1. 先理解 React 的核心理念

  5. 学习 Hooks（useState、useEffect 等）
  6. 最后做一个完整的 Todo 应用

本文基于 React 19（当前最新稳定版本）编写，使用函数式组件 + Hooks。
如果你在网上看到 class Component、this.state 这种写法，那是 React 的旧版 Class 组件，现代 React 开发已全面转向函数式组件。

一、React 是什么？为什么需要它？

1.1 框架的诞生背景

如果你已经学过原生 JS 操作 DOM，你一定经历过这些痛苦：

  • 数据变了，你得手动找到对应的 DOM 元素，调用 innerHTML 或 textContent 更新；
  • 多个地方用同一份数据，你得逐个修改，遗漏一个就会出现 Bug；
  • 页面逻辑变复杂后，代码里到处是 document.querySelector 和事件绑定，改一个怕牵连一片。

React（由 Facebook/Meta 开发维护）就是为了解决这些问题而生的。

React 的核心理念：**UI = f(state)**。页面（UI）是状态（state）的函数——你只需要管理好数据，React 负责把数据高效地渲染到页面上。

1.2 React 的核心特征

  • 声明式：你描述”页面应该长什么样”，React 自动帮你更新 DOM
  • 组件化：把页面拆成独立的、可复用的组件树
  • 单向数据流：数据自上而下流动，让状态变化可预测
  • 虚拟 DOM：React 在内存中维护一份”虚拟 DOM”，通过高效的 diff 算法最小化真实 DOM 操作
  • JSX 语法：在 JS 中写类似 HTML 的代码，模板与逻辑合一

React 是全球使用最广泛的前端框架之一，由 Facebook 在 2013 年开源。它的生态非常庞大：Next.js（全栈框架）、React Native（移动端开发）等都基于 React。

三、JSX：React 的”模板语言”

3.1 什么是 JSX？

JSX（JavaScript XML）是 React 的核心语法。它让你在 JavaScript 中写类似 HTML 的代码：

但 JSX 不是 HTML，它有以下关键区别：

特性 HTML JSX
class 属性 class className
for 属性 for htmlFor
自闭合标签 <br> 或 <br/> 必须 <br />
行内样式 style="color: red" style={{ color: 'red' }}
条件渲染 用 JS 拼接 HTML 用三元表达式或 &&
注释 <!-- 注释 --> {/* 注释 */}

记住：JSX 本质上是 JavaScript，不是 HTML。它最终会被编译成 React.createElement() 函数调用。
所以属性名用的是 JS 的命名规范（camelCase），而不是 HTML 的命名规范。

3.2 在 JSX 中嵌入表达式

原理补充

  • {} 里可以放任何有返回值的表达式：变量、三元表达式、函数调用、数学运算等。
  • {count > 0 && '有新消息'} 是 React 中常见的”短路求值”模式：前面为 true 时渲染后面的内容，为 false 时什么都不渲染。
  • {} 里不能放语句（如 if、for），只能放表达式。

五、Props：组件间的数据传递

5.1 什么是 Props？

Props（properties 的缩写）是父组件向子组件传递数据的方式。你可以把它理解为”组件的参数”。

原理补充

  • Props 是只读的——子组件不能修改 props。这是 React 的核心原则之一。
  • 用花括号 {} 解构 props 是最常见的写法：function UserCard({ name, age }) 比 function UserCard(props) 然后 props.name 更简洁。
  • Props 可以传递任何 JS 值：字符串、数字、布尔值、对象、数组，甚至函数。

六、State：组件的记忆

6.1 useState Hook

State（状态）是组件内部的”记忆”。当 state 变化时，React 会自动重新渲染组件。

useState 是 React 提供的最基础的 Hook：

原理补充

  • useState 返回一个数组：第一个元素是当前状态值，第二个元素是更新该状态的函数。
  • 用数组解构 const [count, setCount] 可以随意命名变量。
  • 调用 setCount(newValue) 会触发组件重新渲染——这是 React 响应式的核心机制。
  • setCount 的命名约定是 set + 状态名的首字母大写形式。

重要：不要直接修改 state 变量！

6.3 管理复杂状态

不可变更新原则：React 通过比较对象的引用（内存地址）来判断 state 是否变化。
如果你直接修改原对象的属性（user.age = 19），引用没变，React 认为 state 没变，就不会重新渲染。
所以必须用展开运算符 { ...user, age: 19 } 创建一个新对象。

7.1 基本事件绑定

7.2 传递参数

原理补充

  • 不能直接写 onClick={handleDelete(index)}，因为这会在渲染时立即执行函数。
  • 必须用箭头函数包一层：onClick={() => handleDelete(index)}，这样才会在点击时才执行。
  • 这和原生 JS 中 addEventListener 传回调函数是同一个思想。

九、副作用与生命周期：useEffect

9.1 什么是副作用？

“副作用”是指组件渲染之外的操作，比如：

  • 发送网络请求
  • 操作 DOM
  • 设置定时器
  • 订阅外部数据

useEffect 就是 React 处理副作用的 Hook。

9.2 依赖数组的三种形态

依赖数组 执行时机 适用场景
不传 每次渲染后 很少用，容易导致无限循环
[] 仅首次渲染 初始化、一次性请求
[dep1, dep2] 首次 + 依赖变化 根据参数变化重新执行

9.3 清理函数

有些副作用需要在组件卸载或重新执行前”清理”（取消订阅、清除定时器等）：

原理补充

  • useEffect 的回调函数可以返回一个清理函数。
  • 清理函数会在两个时机执行：组件卸载时、effect 重新执行前（清理上一次的副作用）。
  • 这保证了不会出现”组件已经没了，定时器还在跑”的内存泄漏问题。

一个简单的记忆：

  • useEffect(() => { ... }, []) ≈ Vue 的 onMounted（首次渲染后执行）
  • useEffect(() => { ... }, [dep]) ≈ Vue 的 watch(dep, ...)（依赖变化时执行）
  • useEffect(() => { return () => { ... } }, []) ≈ Vue 的 onUnmounted（清理工作）

十、表单处理：受控组件

在 React 中，表单元素（input、textarea、select）的值由 React state 控制，称为受控组件：

原理补充

  • 受控组件的核心思想：input 的值由 state 决定，用户输入时通过 onChange 更新 state。

在完成 Todo 应用后，你可能注意到了一个模式：每次更新 state，我们都在创建新数据，而不是修改原数据。

这就是 React 单向数据流的体现：数据自上而下流动，事件（回调函数）自下而上传递。

React 和 Vue 在状态管理上的哲学差异：

  • Vue：每个组件可以直接修改自己的状态（user.age++），Vue 的响应式系统会自动追踪变化。
  • React：强调不可变性，每次更新都必须创建新的状态值（setUser({ ...user, age: user.age + 1 })），通过 setter 函数触发更新。

两种方式各有优劣，但 React 的不可变性让状态变化更加可预测，便于调试和测试。

下一步…

如果你已经读到这里，说明你已经掌握了 React 的核心基础。建议按这个节奏继续：

  1. 动手改造 Todo 应用：添加”全部/未完成/已完成”筛选功能
  2. 学习 React Router：实现多页面切换（单页应用的基础）
  3. 学习 useContext：解决跨层级组件通信问题
  4. 学习 useReducer：管理更复杂的状态逻辑（类似 Redux 的本地版）
  5. 学习 Next.js：React 的全栈框架，支持服务端渲染
  6. 部署你的 React 应用：npm run build 后把 dist/ 目录部署到服务器

React 的学习曲线比 Vue 稍陡，但掌握后你会发现它的思想非常清晰：一切都是函数，状态不可变，数据单向流。
不要在初学阶段纠结”虚拟 DOM 的 diff 算法是怎么实现的”，先享受组件化开发的便利，等到对 React 足够熟悉后再去深入原理。
