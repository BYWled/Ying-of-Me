TypeScript 不是一门全新的语言，它是 JavaScript 的超集。
所有合法的 JS 代码都是合法的 TS 代码——TS 只是在 JS 的基础上增加了类型系统。

一、TypeScript 是什么？为什么需要它？

1.1 JavaScript 的痛点

1.2 TypeScript 的解决方案

TypeScript 在 JavaScript 的基础上增加了一层静态类型检查：

TypeScript 的核心价值：把运行时的类型错误，提前到编写代码时发现。

1.3 TypeScript 的核心特征

  • 静态类型：在代码运行前就能发现类型错误
  • 类型推断：不需要处处写类型注解，TS 能自动推断大部分类型
  • 渐进式：可以逐步把 JS 项目迁移为 TS，不需要一步到位
  • 强大的 IDE 支持：自动补全、类型提示、重构能力大幅提升
  • 编译为 JS：浏览器不能直接运行 TS，最终会编译成标准 JS

TypeScript 由微软在 2012 年发布，目前已成为前端工程化的事实标准。
Vue 3、React、Angular、Next.js 等主流框架的源码全部使用 TypeScript 编写。

3.5 特殊类型

**any vs unknown**：

  • any 会彻底关闭类型检查，等于告诉 TypeScript “别管我”。
  • unknown 是类型安全的替代品——你可以接收任何值，但使用前必须先检查类型。

优先用 unknown，只在实在无法确定类型时才用 any。

4.2 interface vs type

特性 interface type
描述对象形状 ✅ ✅
联合类型 ❌ ✅ type A = string | number
交叉类型（合并） ✅ extends ✅ &

六、泛型

泛型（Generics）是 TypeScript 中最强大的特性之一，它让你写出可复用且类型安全的代码。

6.1 泛型函数

原理补充

  • <T> 是类型参数，T 只是一个约定俗成的名字（代表 Type），你可以用任何名字。
  • 调用函数时，TypeScript 会根据传入的参数自动推断 T 的类型。
  • 你也可以手动指定：getFirst<number>([1, 2, 3])。

下一步…

如果你已经读到这里，说明你已经掌握了 TypeScript 的核心基础。建议按这个节奏继续：

  1. 把一个现有 JS 项目迁移为 TS：从重命名 .js → .ts 开始，逐步添加类型
  2. 学习条件类型：T extends U ? X : Y，TypeScript 类型系统的”三元表达式”
  3. 学习映射类型：遍历对象属性生成新类型
  4. 在 React/Vue 中使用 TS：给组件的 Props 和 State 添加类型
  5. 阅读开源项目源码：Vue 3、React 等项目的源码都是学习 TS 的好材料

TypeScript 的学习曲线比 JavaScript 陡峭，但它的回报也是巨大的：
更少的 Bug、更好的 IDE 提示、更自信的重构能力。
不要一开始就追求”类型体操”，先把基础类型和接口用好，就已经能覆盖 90% 的场景了。

关于AI的使用：

你可以用 AI 来辅助理解和查找资料，但不要直接复制 AI 生成的代码，要自己动手写一遍。

TypeScript 的类型错误是最好的老师——每个报错都在告诉你”你的理解有偏差”。认真阅读错误信息，比看任何教程都管用。
